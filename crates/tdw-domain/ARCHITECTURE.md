# tdw-domain — Architecture

## Module map

The crate is a single `lib.rs`. It groups three kinds of items:

| Group | Items |
| --- | --- |
| BOM record types | `MarketDataBar`, `Tick`, `Quote`, `Trade`, `BookLevel`, `CorporateAction`, `FxRate`, `EquityHistoricalData`, `OrderEvent`, `PositionSnapshot`, `NewsSentiment`, `FundamentalMetric`, `StrategySignal`, `RiskMetric`, `TradingCalendarEvent`, `OperationalEvent`, `ReferenceInstrument`, `Instrument`, `CostFeeEvent`, `ResearchNote` |
| Enums | `AssetClass`, `OrderSide`, `OrderStatus`, `TimeGranularity` |
| Reference-data entities | `Country`, `Currency`, `Exchange`, `Issuer`, `ClassificationNode` |
| Reference-id newtypes | `Figi`, `Isin`, `Cusip`, `Sedol`, `Mic`, `CountryAlpha2`, `CurrencyCode` (fixed length); `IssuerId`, `ClassificationCode` (non-empty) |
| Constants / errors | `BOM_SCHEMA_NAMES`, `ReferenceIdError` |

## Key types and traits

- **Record structs** derive `Clone, Debug, PartialEq, Serialize, Deserialize,
  JsonSchema, Validate`. Validation rules are expressed declaratively with
  `#[validate(...)]` attributes (e.g. `length(min = 1)`, `range(min = 0.0)`,
  `range(min = -1.0, max = 1.0)` for sentiment).
- **Reference-id newtypes** wrap a `String` with `#[serde(transparent)]` so they
  serialize as a bare string. They are generated by two internal macros:
  - `fixed_len_id!` — enforces an exact character count in `new()`.
  - `non_empty_id!` — enforces a non-empty, trimmed value in `new()`.
  Both expose `new(impl Into<String>) -> Result<Self, ReferenceIdError>` and
  `as_str(&self) -> &str`, and derive `Ord`/`Hash` so they work as map keys.
- **`ReferenceIdError`** is a hand-written `enum` (`WrongLength`, `Empty`) that
  implements `Display` + `std::error::Error`.

## Data flow

`tdw-domain` sits at the bottom of the dependency graph. The flow is:

```
producer code ──constructs──▶ domain struct ──.validate()──▶ Result<(), ValidationErrors>
                                   │
                                   ├──serde──▶ JSON / row payloads (ingest, outbox, CDC)
                                   └──schemars──▶ JSON Schema (registry / codegen)
```

Two distinct validation paths coexist:

1. **Field validation** via `validator` — call `value.validate()` on any record
   to check declared constraints. Used by ingest/seed paths before persistence.
2. **Constructor validation** via the newtype `new()` functions — malformed
   identifiers cannot be constructed at all (parse, don't validate later).

## Invariants

- Every record type is `serde`-round-trippable; the JSON Schema produced by
  `schemars` is the contract other languages depend on.
- `BOM_SCHEMA_NAMES` has exactly 11 entries and names the BOM families. Downstream
  crates (e.g. `tdw-sql-codegen`) read its length, so it must stay stable.
- Fixed-width newtypes count **characters** (`chars().count()`), not bytes, so the
  length checks are Unicode-aware.
- Price/size/volume fields are non-negative (`range(min = 0.0)`); sentiment scores
  are bounded to `[-1.0, 1.0]`.
- No type performs I/O or holds mutable global state; construction and validation
  are pure and deterministic.
