# Release Notes — v1.8.0

> **Status: pending tag.** Bundles the OpenBB *ecosystem*-parity program —
> 10 waves, PRs #444–#453 — merged to `main` after the v1.7.1 patch.

The **OpenBB ecosystem-parity release — beyond command parity.** v1.4.0–v1.6.0
reached **total OpenBB command/data parity** and v1.7.x shipped the **FinX
Partner**. v1.8.0 closes the other half of OpenBB parity: the capability
*surfaces* the OpenBB **organization** ships across its whole GitHub org —
**beyond the Platform's data/command surface**. The `openbb-ecosystem-p1`
campaign (G001–G010) adds **computed analytics** OpenBB's Platform does not
compute, four new **operator/client surfaces**, and a **provider scaffolder**.

This is a **MINOR** release: every change is a backward-compatible **addition** —
new crates, new compute routes, new feature-gated surfaces, and a separate
TypeScript add-in package. The native `gui` / `discord` / `telegram` / `charts`
features are **off by default**, so default builds are byte-for-byte unaffected.
No protocol, persistence-schema, or operator-contract breaks.

## What's new

### Computed analytics — where FinX *exceeds* the Platform
The OpenBB Platform is a data-aggregation layer; its `derivatives`/`forecast`
routers largely *fetch* vendor-served numbers. This release adds analytics FinX
**computes** itself — deterministic, offline `Compute` routes (no provider, no
network, every figure reproducible from its inputs):

- **Option pricing & greeks (#444, G001):** `tdw-quant-options` — Black-Scholes,
  the full greek set, implied-vol inversion, a binomial (CRR) tree, and
  Monte-Carlo, all pure-Rust.
- **Classical forecasting (#446, G003):** `tdw-analytics-forecast` — naive /
  seasonal-naive / RWD baselines, Holt-Winters / ETS, Theta, MSTL, lag-feature
  linear regression, an expanding-window backtest harness, RMSE / MAE / MAPE /
  SMAPE measures, and a quantile-band anomaly scan, as `forecast/*` routes.
- **AutoARIMA (#452, G008):** `ARIMA(p, d, q)` (Hannan-Rissanen) and `AutoARIMA`
  (Hyndman-Khandakar stepwise search) added to `tdw-analytics-forecast`, as the
  `forecast/arima` and `forecast/autoarima` routes. OpenBB's Platform does not
  compute these.

### New surfaces
- **Desktop chart-render host (#448, G005):** `tdw-chart-host` — a pure-Rust
  Plotly host-page assembler with an optional native window behind the
  off-by-default `gui` feature (`wry`/`tao`); the PyWry-equivalent.
- **Workspace control-plane MCP (#450, G006):** `tdw-workspace-mcp` —
  dashboard/widget CRUD + layout + navigate over a catalog-validated
  `WorkspaceState` that serializes to `apps.json`.
- **Discord/Telegram chat-bot (#451, G007):** `tdw-bot` — a pure-Rust offline bot
  core (parser + router + `BotResponse` + chart payload) with feature-gated
  `discord`/`telegram` transports and a `charts` PNG path; the `openbb-bot`-equivalent.
- **Excel / Office add-in (#453, G009):** `integrations/excel-addin` — Office.js
  custom functions (`FINX.GET` / `FINX.BYOD` / `FINX.ROUTES`) over the FinX REST
  catalog.

### Developer surface
- **Provider scaffolder (#445, G002):** `xtask new-provider` scaffolds a new
  `tdw-provider-<name>` crate against `tdw_core::Fetcher` — the FinX equivalent of
  OpenBB's provider-extension cookiecutter.
- **Workspace-SDK completeness (#447, G004):** the Workspace widgets/apps backend
  (`tdw-widgets`) and copilot bridge (`tdw-openbb-agent`) brought to
  SDK-completeness (citations, the agent contract).

## Deliberate deferrals

- **Deep-learning forecasting is deferred, not built.** OpenBB's neural
  forecasters (RNN/LSTM/GRU, NBEATS, NHITS, TCN, TFT, Transformer) are built on
  `darts`/`torch` — a large native dependency that is fundamentally at odds with
  the pure-Rust, zero-heavy-dependency, deterministic, offline-compute posture of
  the analytics surface. The decision and the supported future path (an
  off-by-default `candle`/`burn` feature, or a sidecar — **never** `torch`/`darts`
  in the core) are recorded in
  [`docs/roadmap/dl-forecasting-deferral.md`](../roadmap/dl-forecasting-deferral.md).
  The classical suite (G003) + ARIMA/AutoARIMA (G008) already cover the keyless,
  deterministic majority of OpenBB's forecasting surface.
- **The Excel add-in is a separate TypeScript package**
  (`integrations/excel-addin`), not a Rust crate. Office.js add-ins run in the
  Office host's JavaScript runtime, so this is the deliberate, idiomatic non-Rust
  deliverable. It is a thin client over the same REST catalog (all real logic in
  its unit-tested pure `src/lib`), adding no Rust workspace surface and no native
  dependency.

## Upgrade notes

- **No breaking changes.** All additions are backward-compatible: new crates, new
  `Compute` routes, new feature-gated surfaces, and a separate TS package. Existing
  MCP / REST / CLI / Workspace contracts are unchanged.
- **New native surfaces are OFF by default.** The `gui` (chart-host native
  window), `discord`, `telegram`, and `charts` (PNG) features are all opt-in
  cargo features — a default `cargo build`/`cargo install` pulls **none** of their
  native/heavy dependencies and is unaffected. Enable them explicitly to use the
  desktop chart window or the bot transports.
- **The catalog grew to 284 routes** (the new `forecast/*` and option-pricing
  `Compute` routes, plus the data-parity routes landed since v1.7.0), all derived
  from the one typed catalog (REST + OpenAPI + Python SDK + Workspace widgets + MCP
  tools stay in lockstep, drift-gated by `xtask catalog-check` / `openapi-check`).
- **Carries the v1.7.1 FinX Partner integrity patch** (released 2026-06-14) — see
  [`docs/release/v1.7.1-notes.md`](v1.7.1-notes.md).
