# Release Notes — v1.3.0

> **Status: released.** Tagged v1.3.0 on 2026-06-11.

The self-hosted warehouse release. v1.2.0 made the MCP financial-data server
(Product ①) production-ready and released; v1.3.0 does the same for the
**self-hosted warehouse stack** (Product ②) — ClickHouse for time-series
storage, Qdrant for vector search, Meilisearch for full-text, PostgreSQL for
relational state, all composed behind the `tdw-service` API and `tdw-worker`
pipeline.

## Highlights

### Production-ready compose stack

The `full` compose profile is now operator-grade (#282):

- Every image is pinned to a specific digest with a rationale comment — no
  silent upgrades on `docker compose pull`.
- Healthcheck coverage expanded from 6 to 9 services, with each probe
  cross-matched to the corresponding CI wait-step so local and CI behaviour
  stay in sync. In-container probe tooling is matched to what each image
  actually ships (no `curl` in distroless/ClickHouse images — probes use the
  tools that exist).
- Named volumes replace anonymous mounts — data survives a `docker compose
  down` without `--volumes`.
- `.env.example` covers every variable the stack consumes, with inline
  commentary on where each value comes from.

### Operator runbooks

Two operator documents shipped with this release (#289):

- [`docs/release/backup-restore-runbook.md`](backup-restore-runbook.md) —
  volume backup procedures for each storage engine (ClickHouse detach/attach,
  Qdrant snapshot, Meilisearch dump, PostgreSQL `pg_dump`), restore steps, and
  a smoke-test checklist.
- [`docs/release/upgrade-runbook.md`](upgrade-runbook.md) — rolling image-pin
  upgrade procedure, including `xtask migrate` (the dry-run migration planner)
  and a rollback path for each storage engine.

### OIDC IdP integration guide

[`docs/release/oidc-idp-setup.md`](oidc-idp-setup.md) (#290) covers the three
most common IdPs — Keycloak, Auth0, and Microsoft Entra — with:

- Mapping tables from each IdP's terminology to the TDW OIDC contract fields.
- A fail-closed drill checklist: what to verify before putting the gate in
  front of production traffic.
- A token-rotation runbook with no-downtime key rollover steps.
- Claim values machine-verified against the auth contract doc — no stale
  copy-paste from provider tutorials.

### Warehouse install + 15-minute eval path

[`docs/products/warehouse-install.md`](../products/warehouse-install.md) (#288)
is the end-to-end getting-started document for Product ②:

- Compose `full` profile quickstart: prerequisites, first boot, health
  verification.
- Checkpoint-gated evaluation sequence designed to reach live data flowing
  through the stack in under 15 minutes.
- Honest caveats: the nightly Binance→ClickHouse soak requires a reachable
  Binance endpoint (geo-blocked on some runners); keyed provider legs require
  the corresponding API key.

### Cross-backend behavioural conformance

Three parametrised conformance suites now enforce identical semantics across
all backends (in-memory, SQLite, PostgreSQL) (#283, #284, #285):

- **Worker queue** (#283): enqueue, dequeue, ack, nack, dead-letter, and
  duplicate-enqueue contracts. This suite caught a real divergence: the
  in-memory backend accepted duplicate enqueues idempotently while the durable
  backends returned an error — now unified per the D3 contract.
- **Outbox** (#284): at-least-once delivery, ordering, and idempotent
  processing contracts with relative assertions (shared-table-safe).
- **Cost ledger** (#285): idempotent at-least-once append, accumulation, and
  session-scoping contracts.

All three suites run in CI on every PR. "All backends behave identically" is
now an executable guarantee, not a design assertion.

### Nightly ingestion soak

The nightly job (#293) now includes a bounded Binance→ClickHouse ingestion
soak: drives the live websocket feed, waits for rows to land, and asserts
counts. The job is geo-block-tolerant — a reachability probe gates every soak
step; an unreachable exchange emits a structured skip summary instead of
failing the nightly. The fix PR (#294) also wired the required
`TDW_MCP_HTTP_TOKEN` into the e2e-full job (was silently missing) and added
Binance HTTP 451 skip logic to the live-smoke job.

### Commercial support live

`SUPPORT.md` and the announcement pricing paragraph landed with this release
(#300): community support via GitHub Issues and three commercial tiers
(Starter, Professional, Enterprise). Closes decision D2.

## Upgrade notes

- **Named volumes.** If you ran the `full` profile under v1.2.0, your data is
  in anonymous volumes. Before upgrading, back up with the procedures in
  [`docs/release/backup-restore-runbook.md`](backup-restore-runbook.md) and
  restore into the named volumes after the first `docker compose up` with the
  new config.
- **Pinned images.** `docker compose pull` will no longer silently upgrade
  storage engines. To update a pin, edit the digest in `docker-compose.yml`
  and follow the upgrade runbook.
- **OIDC claims.** No changes to the OIDC contract in this release. The setup
  guide is new documentation for an existing feature.
- **Backend conformance.** If you relied on the in-memory worker backend's
  previously-idempotent duplicate-enqueue behaviour, it now returns an error
  consistent with the durable backends. Update callers to de-duplicate before
  enqueuing or to handle the error.
- No protocol, persistence schema, or operator-contract breaks beyond the
  duplicate-enqueue alignment noted above: MINOR release.
