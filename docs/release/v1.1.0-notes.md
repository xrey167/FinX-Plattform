# Release Notes — v1.1.0 (draft)

> **Status: DRAFT / pending tag.** This is the operator-facing draft for the
> `v1.1.0` release. The release is **not yet cut**: no tag, no GitHub release.
> A final pre-tag pass reconciles the pending PRs (see
> [`CHANGELOG.md`](../../CHANGELOG.md) → *Pending — close before tag*) and dates

`v1.1.0` is a security-, observability-, and production-readiness release on top
of `v1.0.0`. The full change list lives in [`CHANGELOG.md`](../../CHANGELOG.md);
this page summarizes operator-facing highlights and upgrade actions.

## Highlights

### Security hardening

- **Cryptographic OIDC verification** (#150). `tdw-auth-oidc` now verifies JWT
  signatures (RS256/ES256 by `kid`) and enforces `exp`/`nbf`/`iat`, issuer, and
  audience, failing closed. `alg:none` and HMAC tokens are rejected
  (alg-confusion defence). Verifying keys come from the configured JWKS; remote
  JWKS fetch remains out of scope.
- **Constant-time bearer-token comparison** (#150). `TDW_MCP_HTTP_TOKEN` is now
  compared in constant time over fixed-width digests, removing a timing side
  channel.
- **Loopback-default daemon bind with a security warning** (#150). The daemon
  TCP transport defaults to `127.0.0.1:7878` and logs a `SECURITY WARNING` when
  bound to a non-loopback address with no auth-backed policy attached.

### Observability and graceful drain

- `/health`, `/ready`, `/metrics` endpoints and graceful drain for the daemon,
  worker, and MCP server (**#161, pending merge at draft time** — confirm before
  tagging).

### Real-engine `live` profile

- **Real storage/compute engines by default in the `live` profile** (#157). The
  `live` Compose profile now wires the real ClickHouse / Postgres / Qdrant /
  Meilisearch / S3 engines instead of in-memory stand-ins, so the deployed stack
  exercises production paths. Default offline builds are unchanged.

### Dispatch completeness

- **Registry-driven dispatch end to end** (#158). Ingest runs through the
  provider registry, a `ToolRegistry` routes tool/MCP calls, and the wasm UDF
  runtime is reachable from the daemon dispatch path.
- **Worker dead-letter operator surface** (#153). `tdw-worker dead-letter list`
  / `dead-letter replay` plus a bounded-concurrency clamp.

### Documentation sweep

- Consolidated `TDW_*` configuration reference (#149,
  [`docs/CONFIGURATION.md`](../CONFIGURATION.md)).
- README + ARCHITECTURE + examples for all 113 crates
  (**#164–#168, #170–#172, pending merge at draft time**).

## Upgrade notes

Read these before upgrading an exposed deployment.

### Breaking for exposed deployments: loopback-default daemon bind

The daemon TCP transport defaults to **loopback** (`127.0.0.1:7878`). If your
deployment previously reached the daemon across containers or hosts via an
implicit non-loopback bind, you must now **explicitly** set
`TDW_DAEMON_TCP_BIND` (e.g. `0.0.0.0:7878`) **and** attach an auth-backed policy.
The daemon logs a `SECURITY WARNING` when bound to a non-loopback address
without auth. Do not expose an unauthenticated daemon to a routable network.

### Breaking: partial OIDC config is now a hard startup error

A `prod`/`production` boot with **some but not all** `TDW_OIDC_*` variables set
(or with invalid JWKS/claims) now **refuses to start**, printing a diagnostic
that lists every missing variable. Previously a partial config could boot in a
degraded state. Either provide a complete OIDC configuration or leave it fully
unset (the fully-unset path keeps the existing fail-closed behavior: the daemon
starts and dispatches return `Failed`). `OidcPolicyError::MissingEnvVar` was
replaced by `MissingEnvVars(Vec<&'static str>)`.

### Configuration reference

All `TDW_*` environment variables, profile selection, and the `live` Compose
setup are documented in [`docs/CONFIGURATION.md`](../CONFIGURATION.md). Start
there when reconciling your environment for the upgrade.

## Release process

This release follows the tag-driven process in [`docs/release.md`](../release.md):

1. Reconcile the changelog against `git log v1.0.0..HEAD --oneline` and fold in
   any pending PRs.
2. Run `cargo run -p xtask -- prerelease-check` and confirm `prerelease-check:
   PASS`.
3. Tag `v1.1.0` from `main` and let the release workflow publish archives,
   checksums, attestations, and GHCR images.

The workspace `Cargo.toml` `version` field is intentionally **not** bumped per
release — releases are tag-driven (see the *Versioning* note in
[`CHANGELOG.md`](../../CHANGELOG.md) and the per-release notes since `v0.2.0`).
