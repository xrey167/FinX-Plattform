# Release Notes — v1.7.1

> **Status: pending tag.** A patch on the v1.7.0 FinX Partner release, off `main`.

The **FinX Partner integrity patch.** A post-release `tdw-partner` re-review
confirmed the four release-critical safety properties (audit-only autonomy, the
escalation/`AwaitingHuman` predicate, the `>= Learning` write gate, and the
cohesion/anti-duplication guard) all hold and are genuinely implemented. It also
found that the learning loop's *behavior-shaping* was wired to nothing live: the
W4.2 learned-route reshaping and the W4.3/W4.4 walk-forward harness existed only
under `#[cfg(test)]`, so the documented "a learned preference reshapes behavior
this turn" promise was structurally unreachable in any shipped surface. v1.7.1
closes those integrity gaps.

This is a **PATCH** release: all changes are backward-compatible (new fields on
`TurnOutcome` and the `tdw.partner.undo` plan; a new opt-in `eval-harness`
feature). No protocol, persistence-schema, or operator-contract breaks.

## What changed

### Learned-route reshaping fires on a live turn (HIGH)
`PartnerCore` gains a gated `InferEngine` seam (`with_infer_engine`). A turn now
reads the installed — hence promoted-past-B9 — induced rule set via
`walk_forward::routing_hints_from`, maps the induced hints to a route-preference
list with `route_preferences_from_hints`, and threads it onto the
`LearningState` snapshot **before** the resolution is reshaped. So a learned
preference moves the preferred route ahead on a real `PartnerCore::turn`, not
only in a `learning.rs` unit test. The preference is always the gated signal
(read off the engine the daemon hot-reloads) and never caller-supplied, so the
audit-only/gated posture is preserved; the trust-dial gate still dominates, so a
below-`Learning` principal is never reshaped. A live-turn test asserts the
preferred route leads.

### Walk-forward usefulness is a public eval entry point (HIGH)
`walk_forward::walk_forward_usefulness` — the deterministic offline replay that
proves the "more useful with use" metric rose across a learning epoch — is
promoted out of `#[cfg(test)]` to a public function behind the new `eval-harness`
feature. The gated eval loop / a benchmark gate can now compute a
`UsefulnessReport`, rather than the metric living only inside a unit test. The
heavy offline `tdw-eval-runner` replay dependency stays out of the default
(leaf) build via the feature flag, preserving `tdw-partner`'s leaf posture.

### Undo respects `AwaitingHuman` (MEDIUM)
`tdw.partner.undo` now surfaces the action's `status` and a `needs_confirmation`
flag. An action the escalation predicate flagged `AwaitingHuman` (high-impact /
low-confidence / irreversible) no longer yields a ready-to-execute reversal: the
plan still describes the cold-plane move (so a human can see what *would*
happen), but `needs_confirmation` is `true` so the daemon refuses to apply it
without explicit human confirmation — the human-in-the-loop posture survives into
the reversal surface.

### Model error surfaced on the turn outcome (MEDIUM)
`TurnOutcome` gains `model_error: Option<String>`. A `complete_streaming` failure
is rendered both as the usual `Reasoning("Model error: …")` event (so the stream
still closes cleanly) **and** as `model_error` on the outcome, so a write-back
caller can distinguish a failed/partial generation from a successful one and must
not persist a partial answer as complete.

### Ticker stop-words expanded (LOW)
`TICKER_STOP_WORDS` now covers common macro/geo/role acronyms (`US`, `EU`, `CPI`,
`GDP`, `ETF`, …), so a question like "What is US CPI doing?" does not mine `US`
as a symbol on a symbol-keyed equity route.
