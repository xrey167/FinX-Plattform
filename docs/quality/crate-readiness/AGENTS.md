# crate-readiness

## Purpose

Per-crate audit worksheets and the cross-crate readiness matrix. Each
worksheet records the latest tranche audit for one crate: dependency edges,
test attribute counts, baseline-scan signals, and a verdict
(`Ready with follow-ups` / `Pending` / blocker). The matrix
(`matrix.md`) is the at-a-glance index over all worksheets.

These artifacts are the evidence packet for the original tranche audits and
later production-functional passes. When a crate's `Verdict` is anything other
than `Pending`, its worksheet is expected to have substantive audit notes.

## Key Files

| File | Description |
|------|-------------|
| `README.md` | Orientation for the worksheets and how to refresh them. |
| `matrix.md` | One row per crate: tranche, targets, dep edges, test count, verdict. |
| `dependency-topology.md` | Cross-crate dependency edges rendered for review. |
| `tdw-*.md` | One worksheet per workspace crate (see Cargo workspace members). |

## For AI Agents

### Working In This Directory

- **One worksheet per crate.** If a crate gets renamed, rename its worksheet
  too and update `matrix.md` + any inbound links.
- The matrix table is generated by tooling but currently maintained by hand
  during the bootstrap. Keep columns in lockstep: every new crate gets a row
  added with `Verdict = Pending` until its tranche audit runs.
- Test-attribute counts in the matrix are the number of `#[test]` /
  `#[tokio::test]` / `#[proptest]` attributes counted by the tranche audit.
  They are a coarse signal, not a coverage metric.
