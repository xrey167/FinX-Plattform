The runtime today & the gap

One runtime, many shells — and the missing link

CLI, TUI, MCP and the service all drive one CommandRunner. Live ingest flows end-to-end into ClickHouse. But dispatched operations hit a daemon with no policy attached, so they terminate as Failed before reaching the engines.

Green = working today · Red dashed = the policy gap blocking dispatched operations
What’s already done

The slice that shipped

Six releases cut on the pre-1.0 cadence — each a coherent, user-visible layer of the warehouse.

v0.1.x

Release packaging

Multi-target signed binary archives + provenance attestations + scanned GHCR images for service / cli / mcp / worker.

v0.2.0

Daemon runtime & MCP surface

ADR-0012 daemon, stateful MCP server over stdio + Streamable HTTP, durable worker schedulers (SQLite + Postgres), live data backend, test-policy ADR.

v0.3.0

Supervised worker & real UDF runtime

Lease-loop worker, wasmi UDF engine with fuel/memory/deny-imports hardening, live backend expansion (ClickHouse + Qdrant + Meili), mutation/loom/fuzz policy.

v0.4.0

Worker dispatch & UDF ABI

Worker dispatches jobs to the daemon; wasm string-in/string-out ABI; sandbox routes to the hardened runtime — UDF hardening scope closed.

v0.5.0

Streaming ClickHouse warehouse

Real persisting ingest, raw tick/trade/quote/book tables, the full FlowField materialized-view tier, a Postgres+ClickHouse reference-entity model, and an optional rskafka broker. Validated on ClickHouse 26.6 + PG 18.

v0.6.0 · today

End-to-end live ingest & deployment surface

Cancellable WS ingest draining to OLAP (restart-safe dedup), live Binance feed + RSI/volatility UDFs, Postgres-backed --serve worker, long-running services in the live profile, and hardened MCP/daemon exposure.

What’s still open

Ordered by severity. The policy gap is the only thing stopping the deployed stack from executing real operations.

What comes next

Four phases to a production gate

Sequenced by dependency, not calendar. Phase A unblocks everything downstream; the gate (G008) is the terminal node.

Phase A

Wire the policy layer

unblocks all

Make the deployed daemon actually execute dispatched operations.

  • Define the policy model: what a policy authorizes (which ops, providers, storage targets) and where it’s configured.
  • Attach a default policy at tdw-service boot so dispatched ops resolve instead of returning Failed.
  • Add an end-to-end smoke: dispatch → policy → CommandRunner → engine → event evidence, on the live profile.
Depends on: nothing · Blocks: a usable live stack, the G008 gate
Phase B

Finish the event spine (G013)

  • Land the durable outbox, session, bus, and snapshot backends from their worktrees onto main.
  • Validate cross-store consistency on Postgres + S3 with the env-gated integration tests already scaffolded.
  • Prune the merged g013-* and g010-* worktrees as each PR lands.
Depends on: Phase A (policy for dispatched persistence) · Parallelizable with Phase C
Phase C

Broaden providers (G011) & the LLM adapter (G012)

  • Promote the Yahoo worktree fetcher to a production transport; harden FRED / Alpaca / Polygon per the transport-status pattern.
  • Land the Anthropic LLM adapter behind the tdw-llm interface (G012).
  • Pick the provider set that matters for personal use — don’t harden all six on principle.
Depends on: storage + runtime (done) · Independent of Phase B
Phase D

Crate hardening → G008 production gate → 1.0

  • Walk G002–G007: replace each crate’s baseline “follow-ups” with real evidence; flip verdicts to Ready.
  • Resolve deferred details: ClickHouse param binding, Qdrant ID normalization, test-policy enforcement cadence.
  • Define and run G008 — the aggregate gate — then cut the first 1.0 tag.
Depends on: Phases A–C complete · Terminal node
What could bite

Risks & mitigations

RiskSeverityMitigation
Policy model under-specified → ad-hoc auth wiring that’s hard to undo High Write a short policy ADR before code; ship a minimal default policy first, expand behind it.
Provider hardening sprawls across all six on principle, not need Med Personal-use project — pick 2–3 providers that you actually query; defer the rest as documented stubs.
“Ready with follow-ups” debt is unbounded → G008 never converges Med Triage each follow-up as blocker vs deferrable up front; G008 only gates on blockers.
Stale worktrees mask which branch is canonical Low git worktree remove + branch delete on every merge; audit the worktree list now.
Live-stack regressions invisible offline (Docker-gated tests) Low CI integration job already runs the gated tests with containers — keep it green; add the Phase-A dispatch smoke to it.
